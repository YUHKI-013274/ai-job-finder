# AI案件獲得システム Ver3.1

クラウドワークスのAI関連案件を毎朝自動取得し、スマホで確認できるシステム。
一度表示した案件・応募済み案件・見送った案件は自動で除外され、同じ案件を何度も見せない。

## 毎朝の使い方

```
1. 朝PCを起動してログインする
2. バックグラウンドで案件取得が自動開始（約5〜6分）
3. Gmailに通知が届く
     件名：【今日の応募候補】S2件 A2件 6月29日
4. メール内のURLをタップしてスマホで案件確認
5. 気になる案件を3件「候補に追加」
6. 「ChatGPTへ共有」ボタンで応募文を一括作成
7. 応募したらいつも通り「案件管理シート」に記入する
   → 次回の自動実行時にシートを読み取り、その案件は自動で完全除外される
     （ターミナル操作は不要。手動で除外したい場合のみ下記の応募済み登録方法を使う）
8. 応募しないと決めた案件は「⏭ 見送り」ボタンを押す（理由を一言入力）
   → 候補リストタブに表示されるコマンドをPCのターミナルで実行すると、
     次回以降その案件が完全に除外される
```

## 仕組み

```
PC起動・ログイン
  ↓ 45秒後に自動実行（スタートアップ登録済み）
  ↓ 案件管理シート（Googleスプレッドシート）から応募済みURLを自動同期
  ↓ クラウドワークス 26キーワード × 案件取得（最低20件を目標）
  ↓ 応募済み・見送り・既出案件を data/*.json と照合して除外
  ↓ リスク・低単価・条件不一致（性別限定/経験年数必須/常駐/地域限定/スクール勧誘/アンケートのみ等）もこの時点で除外（理由付き）
  ↓ ①ライティング一致度 ②ゆうきとの適性 ③受注できる可能性 ④実績作りになるか
    ⑤継続性 ⑥単価 ⑦未経験歓迎 の優先順位でスコア化（未経験歓迎・継続だけでは高評価にならない）
  ↓ S/A/B/Cで評価して「応募候補」「保留」に分類。Sランクはライティング案件のみ
    （SNSデザイン・動画編集・撮影・音声系は未経験歓迎でもS/Aにならない）
  ↓ 高評価の理由を★の数（重要度）付きで表示（例: ★★★★★ ライティング案件）
  ↓ 応募候補が10件未満なら保留から昇格させて10件を確保（昇格分は「枠埋め」表示）
  ↓ GitHub Pages へ自動デプロイ
  ↓ Gmail 通知送信（応募候補ベース）
スマホで確認
```

### 出力の3分類

| 分類 | 内容 |
|---|---|
| 📋 応募候補 | S/Aランク中心。今日応募すべき案件（最低10件を確保。枠埋め分は「枠埋め（保留から昇格）」と表示） |
| ⏸ 保留 | B/Cランクで今回は候補外だが参考になる案件 |
| 🚫 除外 | 応募済み／見送り／既出／単価が低すぎる／条件不一致／リスクありのいずれかに該当（理由を表示。見送りはデフォルト非表示、チェックボックスで表示可） |

同じ案件IDは `data/seen_jobs.json` に記録され、以後ずっと「既出」として除外される。

## 見送り案件の管理方法

応募しないと決めた案件は、案件カードの「⏭ 見送り」ボタンを押して理由を一言入力する
（ブラウザ内に一時保存）。候補リストタブに登録用コマンドが自動生成されるので、
コピーしてPCのターミナルで実行すると `data/job_status.json` に永続登録され、
次回以降その案件は完全に除外される。

```
node mark-skipped.js "<案件IDまたはURL>|見送り理由"
# 複数まとめて登録も可能（URLに":"を含むため区切りは"|"を使用）
node mark-skipped.js "12345678|単価が低い" "https://crowdworks.jp/public/jobs/87654321|条件が合わない"
```

見送り案件は除外タブでもデフォルト非表示（「見送り案件も表示する」チェックボックスで確認可能）。
`data/job_status.json` は将来「返信あり」「契約済み」「不採用」「保留」等のステータスを
追加できる汎用的な構造にしている（`store.js` の `JOB_STATUS` に追加するだけで拡張可能）。

## 応募済みの管理方法

### 基本：案件管理シートに記入するだけ（推奨）

いつも通り [案件管理シート](https://docs.google.com/spreadsheets/d/1POs2Jn9opTMBEBW5kmWn1aAE31IcoxULD-ZiJbZpAhc/edit?gid=0#gid=0)
のC列に案件URLを記入すれば、次回の自動実行時にC列を読み取って
`data/applied_jobs.json` に自動登録され、以後その案件は完全に除外される。
追加の操作は不要（結果が「応募中」「辞退」「不採用」のどれでも、シートに載っていれば除外対象）。

このシートは `.env` の `APPLIED_SHEET_URL` で指定しており、
**「リンクを知っている全員が閲覧者」** 共有になっている必要がある
（無人実行のためログインセッションを使えないため）。

### 補足：シートに書く前に急いで除外したい場合

案件ページの「✅ 応募済み」ボタンでブラウザ内に一時保存し、候補リストタブに
表示されるコマンドをコピーしてPCのターミナルで実行すると即座に登録できる。

```
node mark-applied.js <案件IDまたはURL>
# 複数まとめて登録も可能
node mark-applied.js 12345678 https://crowdworks.jp/public/jobs/87654321
```

## フェーズ設定（実績0件／実績3件／高単価）

`config.js` の `PHASES` で、今の実績フェーズに応じた最低報酬ラインを切り替えられる。
環境変数 `JOB_SEARCH_PHASE` で選択（未設定時は `zero`）。

| フェーズ | 値 | 最低報酬ライン |
|---|---|---|
| 実績0件フェーズ（デフォルト） | `zero` | 1,000円 |
| 実績3件フェーズ | `three` | 5,000円 |
| 高単価フェーズ | `premium` | 15,000円 |

`.env` に `JOB_SEARCH_PHASE=three` のように追加すると次回実行から切り替わる。
（スコアリングの優先順位自体は下記の①〜⑦で固定。フェーズが変えるのは最低報酬ラインのみ）

---

## 評価基準（①〜⑦の優先順位）

「未経験歓迎」「長期継続」だけで高評価にはならない。以下の優先順位でスコア化する。

1. **①ライティングとの一致度**（最重要）— `CATEGORY_TIERS`（`config.js`）でジャンルを判定
   - 最優先（★5）: SEO記事・ブログ記事・記事執筆・AIライティング・商品レビュー・比較記事・コラム・note記事など
   - 優先（★4）: AI画像制作・Canva制作・広告バナー・SNS画像制作
   - 通常（★3）: SNS運用・リサーチ・データ入力・マニュアル作成
   - 優先度低（★1）: 動画編集・Premiere Pro・CapCut・撮影案件・音声編集など（未経験歓迎でもS/Aにはならない）
2. **②ゆうきとの適性** — AI活用・ライティング関連キーワードとの一致量
3. **③受注できる可能性** — サポート体制・クライアント信頼性・応募者数などから判定
4. **④実績作りになるか** — 現在のポートフォリオ（ライティング・AI活用）との相性
5. **⑤継続性** — 継続案件シグナルの有無
6. **⑥単価** — 金額が高いほど加点
7. **⑦未経験歓迎** — 最も軽い重み。単独では高評価にならない

**Sランクの条件**（すべて満たす場合のみ。`evaluator.js` の `meetsSRankConditions`）:
ライティング案件・未経験または初心者歓迎・1,000円以上・継続案件または継続可能性あり・受注できる可能性が高い。
SNSデザインや動画編集は、この条件を満たしてもSランクにはならない（動画編集・撮影・音声系はS/A自体に乗らない）。

高評価の理由は★の数（重要度）付きで表示される（例: `★★★★★ ライティング案件` `★★★★☆ 継続案件の可能性`）。

## カスタマイズ

`config.js` を編集することで以下を変更できます：

- **検索キーワード追加** → `SEARCH_KEYWORDS` 配列に追加
- **除外条件追加** → `EXCLUDE_PATTERNS` に追加（文字列は部分一致、正規表現も混在可）
- **ジャンル優先度の調整** → `CATEGORY_TIERS`（ライティング/デザイン/通常/優先度低の各 `patterns` にキーワードを追加）
- **未経験歓迎系キーワード追加** → `BEGINNER_PATTERNS`
- **受注しやすさの補助シグナル追加** → `SUPPORT_PATTERNS`（サポート体制・マニュアル完備等）
- **継続案件シグナル追加** → `CONTINUITY_PATTERNS` に追加
- **クライアント信頼性シグナル追加** → `CLIENT_TRUST_PATTERNS`（本人確認済み等）に追加
- **今の強みを活かせるAIキーワード追加** → `AI_FRIENDLY_KEYWORDS`（ChatGPT/Canva/SNS運用等）に追加
- **優先しない技術系キーワード追加** → `AI_TECHNICAL_KEYWORDS`（Python開発/システム開発等、加点せず注意喚起のみ）に追加
- **リスクワード追加** → `RISK_PATTERNS` に追加（詐欺・トラブル警戒サイン）
- **評価の重み調整** → `WEIGHTS`（①〜⑦の重み）を変更
- **最低報酬ライン変更** → `PHASES.zero.minPriceYen` など、フェーズごとに変更
- **応募候補の最低件数変更** → `MIN_CANDIDATES`（デフォルト10件）を変更
- **取得件数変更** → `MAX_JOBS`（応募候補の上限。`MIN_CANDIDATES`と合わせるのが基本）・`MAX_HOLDS`（保留の上限）を変更

## トラブルシューティング

| 症状 | 確認場所 |
|---|---|
| Gmail が届かない | `logs\run.log` を確認 |
| 案件が0件 | ネット接続・クラウドワークスのメンテ確認 |
| 応募候補が10件を切る | `logs\run.log` の警告を確認。`SEARCH_KEYWORDS` を増やすか時間を置いて再実行 |
| 応募候補に「枠埋め」が多い | 良案件が少ない日。市場側の要因が大きいが、`PHASE0_PRIORITY_PATTERNS`/`AI_FRIENDLY_KEYWORDS`の調整で多少改善可能 |
| 前に見た案件がまた出てくる | `data/seen_jobs.json` が削除・上書きされていないか確認 |
| 応募済みの案件が再表示される | 案件管理シートのC列にURLが記入されているか、`node mark-applied.js <ID>` で登録したか確認 |
| 見送った案件が再表示される | `node mark-skipped.js "<ID>|理由"` で `data/job_status.json` に登録したか確認 |
| 「案件管理シートの取得に失敗しました」と出る | シートの共有設定が「リンクを知っている全員が閲覧者」になっているか確認 |
| GitHub Pages が更新されない | `git push` のエラーを `logs\run.log` で確認 |
| スタートアップで起動しない | `shell:startup` でショートカットの存在を確認 |
