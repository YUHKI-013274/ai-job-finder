# AI案件獲得システム Ver3.0

クラウドワークスのAI関連案件を毎朝自動取得し、スマホで確認できるシステム。
一度表示した案件・応募済み案件は自動で除外され、同じ案件を何度も見せない。

## 毎朝の使い方

```
1. 朝PCを起動してログインする
2. バックグラウンドで案件取得が自動開始（約5〜6分）
3. Gmailに通知が届く
     件名：【今日の応募候補】S2件 A2件 6月29日
4. メール内のURLをタップしてスマホで案件確認
5. 気になる案件を3件「候補に追加」
6. 「ChatGPTへ共有」ボタンで応募文を一括作成
7. 応募したらいつも通り「案件管理シート」に記入する
   → 次回の自動実行時にシートを読み取り、その案件は自動で完全除外される
     （ターミナル操作は不要。手動で除外したい場合のみ下記の応募済み登録方法を使う）
```

## 仕組み

```
PC起動・ログイン
  ↓ 45秒後に自動実行（スタートアップ登録済み）
  ↓ 案件管理シート（Googleスプレッドシート）から応募済みURLを自動同期
  ↓ クラウドワークス 26キーワード × 案件取得（最低20件を目標）
  ↓ 応募済み・既出案件を data/*.json と照合して除外
  ↓ リスク・低単価・条件不一致もこの時点で除外（理由付き）
  ↓ 残った案件を S/A/B/C で評価し「応募候補」「保留」に分類
  ↓ 応募候補が10件未満なら保留から昇格させて10件を確保（昇格分は「枠埋め」表示）
  ↓ GitHub Pages へ自動デプロイ
  ↓ Gmail 通知送信（応募候補ベース）
スマホで確認
```

### 出力の3分類

| 分類 | 内容 |
|---|---|
| 📋 応募候補 | S/Aランク中心。今日応募すべき案件（最低10件を確保。枠埋め分は「枠埋め（保留から昇格）」と表示） |
| ⏸ 保留 | B/Cランクで今回は候補外だが参考になる案件 |
| 🚫 除外 | 応募済み／既出／単価が低すぎる／条件不一致／リスクありのいずれかに該当（理由を表示） |

同じ案件IDは `data/seen_jobs.json` に記録され、以後ずっと「既出」として除外される。

## ファイル構成

```
ai-job-finder/
  run.js              メイン処理
  scraper.js          クラウドワークス自動取得
  evaluator.js        案件評価・応募候補/保留/除外の分類ロジック
  store.js            既出・応募済みリストの読み書き
  sheet-sync.js       案件管理シート（Googleスプレッドシート）からの応募済み自動同期
  mark-applied.js      応募済み手動登録CLI（node mark-applied.js <ID/URL>）
  config.js           キーワード・除外ルール・単価/リスク基準（カスタマイズ用）
  renderer.js         HTML/Markdown生成
  notifier.js         Gmail通知
  run-daily.bat       自動実行バッチ（ログイン時に起動）
  data/
    seen_jobs.json     過去に表示した全案件（自動更新・二度と表示しない）
    applied_jobs.json  応募済み案件（シート同期 + 手動登録の合算・永久に除外）
  output/
    index.html        GitHub Pagesで公開されるHTML
    latest.html       ローカル確認用
    latest.md         Markdown版（応募候補/保留/除外を一覧化）
  logs/
    run.log           実行ログ（トラブル時に確認）
```

## 応募済みの管理方法

### 基本：案件管理シートに記入するだけ（推奨）

いつも通り [案件管理シート](https://docs.google.com/spreadsheets/d/1POs2Jn9opTMBEBW5kmWn1aAE31IcoxULD-ZiJbZpAhc/edit?gid=0#gid=0)
のC列に案件URLを記入すれば、次回の自動実行時にC列を読み取って
`data/applied_jobs.json` に自動登録され、以後その案件は完全に除外される。
追加の操作は不要（結果が「応募中」「辞退」「不採用」のどれでも、シートに載っていれば除外対象）。

このシートは `.env` の `APPLIED_SHEET_URL` で指定しており、
**「リンクを知っている全員が閲覧者」** 共有になっている必要がある
（無人実行のためログインセッションを使えないため）。

### 補足：シートに書く前に急いで除外したい場合

案件ページの「✅ 応募済み」ボタンでブラウザ内に一時保存し、候補リストタブに
表示されるコマンドをコピーしてPCのターミナルで実行すると即座に登録できる。

```
node mark-applied.js <案件IDまたはURL>
# 複数まとめて登録も可能
node mark-applied.js 12345678 https://crowdworks.jp/public/jobs/87654321
```

## カスタマイズ

`config.js` を編集することで以下を変更できます：

- **検索キーワード追加** → `SEARCH_KEYWORDS` 配列に追加
- **除外ワード追加** → `EXCLUDE_PATTERNS` または `DOWNGRADE_PATTERNS` に追加
- **リスクワード追加** → `RISK_PATTERNS` に追加（詐欺・トラブル警戒サイン）
- **最低報酬ライン変更** → `MIN_PRICE_YEN`（デフォルト3,000円）を変更
- **応募候補の最低件数変更** → `MIN_CANDIDATES`（デフォルト10件）を変更
- **取得件数変更** → `MAX_JOBS`（応募候補の上限。`MIN_CANDIDATES`と合わせるのが基本）・`MAX_HOLDS`（保留の上限）を変更

## トラブルシューティング

| 症状 | 確認場所 |
|---|---|
| Gmail が届かない | `logs\run.log` を確認 |
| 案件が0件 | ネット接続・クラウドワークスのメンテ確認 |
| 応募候補が10件を切る | `logs\run.log` の警告を確認。`SEARCH_KEYWORDS` を増やすか時間を置いて再実行 |
| 応募候補に「枠埋め」が多い | 良案件が少ない日。市場側の要因が大きいが、`DOWNGRADE_PATTERNS`/`A_RANK_KEYWORDS`の調整で多少改善可能 |
| 前に見た案件がまた出てくる | `data/seen_jobs.json` が削除・上書きされていないか確認 |
| 応募済みの案件が再表示される | 案件管理シートのC列にURLが記入されているか、`node mark-applied.js <ID>` で登録したか確認 |
| 「案件管理シートの取得に失敗しました」と出る | シートの共有設定が「リンクを知っている全員が閲覧者」になっているか確認 |
| GitHub Pages が更新されない | `git push` のエラーを `logs\run.log` で確認 |
| スタートアップで起動しない | `shell:startup` でショートカットの存在を確認 |
