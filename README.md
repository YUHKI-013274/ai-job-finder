# AI案件獲得システム Ver4.0

クラウドワークスのAI関連案件を毎朝自動取得し、スマホで確認できるシステム。
一度表示した案件・応募済み案件・見送った案件は自動で除外され、同じ案件を何度も見せない。

**Ver4.0での変更点**: 「応募数確保」優先から「高単価・職能一致・長期資産づくり」優先へフェーズ変更。
SNS運用代行の除外とSNS単発制作の分離、長期資産性スコアの新設、Aランクへの最低条件ゲート追加、
応募候補の枠埋め（無理な10件確保）廃止、Bランクの「成長候補」化、提案文の軸の案件固有化を実施。

## 毎朝の使い方

```
1. 朝PCを起動してログインする
2. バックグラウンドで案件取得が自動開始（約5〜6分）
3. Gmailに通知が届く
     件名：【今日の応募候補】S2件 A2件 6月29日
4. メール内のURLをタップしてスマホで案件確認
5. 気になる案件を3件「候補に追加」
6. 「ChatGPTへ共有」ボタンで応募文を一括作成
7. 応募したらいつも通り「案件管理シート」に記入する
   → 次回の自動実行時にシートを読み取り、その案件は自動で完全除外される
     （ターミナル操作は不要。手動で除外したい場合のみ下記の応募済み登録方法を使う）
8. 応募しないと決めた案件は「⏭ 見送り」ボタンを押す（理由を一言入力）
   → 候補リストタブに表示されるコマンドをPCのターミナルで実行すると、
     次回以降その案件が完全に除外される
```

## 仕組み

```
PC起動・ログイン
  ↓ 45秒後に自動実行（スタートアップ登録済み）
  ↓ 案件管理シート（Googleスプレッドシート）から応募済みURLを自動同期
  ↓ クラウドワークス 26キーワード × 案件取得（最低20件を目標。SNS関連キーワードも維持）
  ↓ 応募済み・見送り・既出案件を data/*.json と照合して除外
  ↓ リスク・低単価・条件不一致（性別限定/経験年数必須/常駐/地域限定/スクール勧誘/アンケートのみ等）・
    SNS運用代行（投稿管理・コメント/DM対応・アカウント運用・フォロワー増加施策等）もこの時点で除外（理由付き）
    ※SNS単発制作（バナー・投稿画像）は運用代行に該当しない限り通常どおり評価する
  ↓ ②職能一致度 ①証拠の強さ（ポートフォリオ活用度）⑥単価 ⑤継続性 ⑧長期資産性 ④受注できる可能性
    ③ゆうきとの適性 ⑦未経験歓迎 の重み付けでスコア化（単価・職能一致・継続性・長期資産性を重視）
  ↓ S/A/B/Cで評価。Sランクはライティング/画像制作/AI活用・業務改善のいずれかで証拠が強い案件のみ。
    Aランクは点数だけでなく最低条件ゲート（職能一致・証拠が証明不足でない・単価または長期資産性が
    一定以上・受注可能性）をすべて満たす場合のみ。満たさない場合は高得点でもBへ下がる
  ↓ 高評価の理由を★の数（重要度）付きで表示。提案文の軸は「職能の組み合わせ→今回できること→
    クライアントへの価値」を案件ごとに組み立てて表示（固定の定型文は使わない）
  ↓ 応募候補（S/A）は無理な枠埋めをせず最大5件まで。Bランクは「成長候補」として分離し、
    不足している証拠・実績（不足資産）を案件ごと・全体集計の両方で表示
  ↓ GitHub Pages へ自動デプロイ
  ↓ Gmail 通知送信（応募候補ベース）
スマホで確認
```

### 出力の4分類

| 分類 | 内容 |
|---|---|
| 📋 応募候補 | S/Aランクかつ単価確認済み。今日応募すべき案件（最大5件。無理な枠埋めはしない） |
| 🌱 成長候補 | Bランク。今後の営業資産づくりにつながる案件。不足資産を表示し、補えば今後S/Aを狙える |
| ⏸ 保留 | Cランク、または単価未確認のS/A |
| 🚫 除外 | 応募済み／見送り／既出／単価が低すぎる／条件不一致／SNS運用代行／リスクありのいずれかに該当（理由を表示。見送りはデフォルト非表示、チェックボックスで表示可） |

同じ案件IDは `data/seen_jobs.json` に記録され、以後ずっと「既出」として除外される。

## 見送り案件の管理方法

応募しないと決めた案件は、案件カードの「⏭ 見送り」ボタンを押して理由を一言入力する
（ブラウザ内に一時保存）。候補リストタブに登録用コマンドが自動生成されるので、
コピーしてPCのターミナルで実行すると `data/job_status.json` に永続登録され、
次回以降その案件は完全に除外される。

```
node mark-skipped.js "<案件IDまたはURL>|見送り理由"
# 複数まとめて登録も可能（URLに":"を含むため区切りは"|"を使用）
node mark-skipped.js "12345678|単価が低い" "https://crowdworks.jp/public/jobs/87654321|条件が合わない"
```

見送り案件は除外タブでもデフォルト非表示（「見送り案件も表示する」チェックボックスで確認可能）。
`data/job_status.json` は将来「返信あり」「契約済み」「不採用」「保留」等のステータスを
追加できる汎用的な構造にしている（`store.js` の `JOB_STATUS` に追加するだけで拡張可能）。

## 応募済みの管理方法

### 基本：案件管理シートに記入するだけ（推奨）

いつも通り [案件管理シート](https://docs.google.com/spreadsheets/d/1POs2Jn9opTMBEBW5kmWn1aAE31IcoxULD-ZiJbZpAhc/edit?gid=0#gid=0)
のC列に案件URLを記入すれば、次回の自動実行時にC列を読み取って
`data/applied_jobs.json` に自動登録され、以後その案件は完全に除外される。
追加の操作は不要（結果が「応募中」「辞退」「不採用」のどれでも、シートに載っていれば除外対象）。

このシートは `.env` の `APPLIED_SHEET_URL` で指定しており、
**「リンクを知っている全員が閲覧者」** 共有になっている必要がある
（無人実行のためログインセッションを使えないため）。

### 補足：シートに書く前に急いで除外したい場合

案件ページの「✅ 応募済み」ボタンでブラウザ内に一時保存し、候補リストタブに
表示されるコマンドをコピーしてPCのターミナルで実行すると即座に登録できる。

```
node mark-applied.js <案件IDまたはURL>
# 複数まとめて登録も可能
node mark-applied.js 12345678 https://crowdworks.jp/public/jobs/87654321
```

## フェーズ設定（実績0件／実績3件／高単価）

`config.js` の `PHASES` で、今の実績フェーズに応じた最低報酬ラインを切り替えられる。
環境変数 `JOB_SEARCH_PHASE` で選択（未設定時は `zero`）。

| フェーズ | 値 | 最低報酬ライン |
|---|---|---|
| 実績0件フェーズ（デフォルト） | `zero` | 1,000円 |
| 実績3件フェーズ | `three` | 5,000円 |
| 高単価フェーズ | `premium` | 15,000円 |

`.env` に `JOB_SEARCH_PHASE=three` のように追加すると次回実行から切り替わる。
（スコアリングの優先順位自体は下記の①〜⑦で固定。フェーズが変えるのは最低報酬ラインのみ）

## 評価基準（①〜⑧・単価/職能一致/継続性/長期資産性を重視）

「未経験歓迎」「応募件数の確保」だけで高評価にはならない。以下の重み（`WEIGHTS`、`config.js`）でスコア化する。

| 項目 | 重み | 内容 |
|---|---|---|
| ②職能一致度 | 6 | `CATEGORY_TIERS`でライティング(★5)／画像制作・AI活用(★4)／通常(★3)／動画・撮影・音声系(★1)を判定 |
| ①証拠の強さ（ポートフォリオ活用度） | 5 | ライティング／画像制作／AI活用・業務改善の3つの営業資料ページのうち、この案件でそのまま使えるかを3段階判定 |
| ⑥単価 | 4 | 金額が高いほど加点（1万円以上★5〜1,000円未満★1） |
| ⑤継続性 | 3 | 継続案件シグナルの有無 |
| ⑧長期資産性 | 3 | 営業資料3カテゴリとの一致・継続性・単価・「実績公開可」等の明言から、営業資産として残る度合いを判定 |
| ④受注できる可能性 | 2.5 | サポート体制・クライアント信頼性・応募者数などから判定 |
| ③ゆうきとの適性 | 2 | AI活用・ライティング関連キーワードとの一致量（SNS運用等の運用系キーワードは対象外） |
| ⑦未経験歓迎 | 0.5 | 最も軽い重み。単独では高評価にならない |

### SNS案件の分離判定（`SNS_OPERATION_EXCLUDE_PATTERNS` / `SNS_SINGLE_CREATION_PATTERNS`）

「SNS」という単語だけで一律除外・一律減点はしない。

- **原則除外**: SNS運用代行・投稿管理・コメント/DM対応・アカウント運用・フォロワー増加施策・バズ施策・
  分析改善を含む継続運用 → `excludeReason: 'SNS運用代行'` で除外タブへ
- **条件付き評価**: SNS用バナー・Instagram投稿画像・広告画像等の単発制作は運用代行を含まない限り
  通常どおり評価（情報設計・飲食経験・商品理解・ポートフォリオが活きる場合のみ高評価になる）

検索キーワードからSNS関連は削除していない（案件内容で運用/単発を判定するため）。

### Sランクの条件（`meetsSRankConditions`）

すべて満たす場合のみ: ライティング／画像制作／AI活用・業務改善のいずれかで主戦場と一致・
証拠が「直接証明」または「強い代替証明」・単価が確認できる・高単価（単価スコア4以上）または
継続案件シグナルあり・長期資産性スコア4以上・受注できる可能性が高い。
通常案件や動画編集・撮影・音声系は、この条件を満たしてもSランクにはならない。

「未経験歓迎」はSランク・Aランクいずれの必須条件にもしていない（⑦未経験歓迎の軽い加点にとどめる）。
これにより、未経験歓迎と書かれていないBtoB資料・業務改善・AI活用案件も、証拠と単価・長期資産性が
十分であればSランクになりうる。

### Aランクの最低条件ゲート（`meetsARankConditions`）— 点数だけで判定しない

合計点でS/Aに届いても、以下をすべて満たさない場合はBへ下げる。

- 動画・撮影・音声系（`low`）ではない
- 職能一致度が一定以上（`categoryScore >= 3`）
- 採用理由の証拠が「証明不足」ではない（`evidenceStrength`）
- 単価スコアまたは長期資産性スコアのいずれかが高い（`priceScore >= 4` または `longTermAssetScore >= 4`）
- 受注できる可能性が一定以上（`winScore >= 3`）

これにより「低単価・低適性だが点数だけ高い案件」がAランクへ大量に入ることを防ぐ。

### 採用理由・証拠の強さ（`computeEvidenceStrength`）

4段階で分類し、案件カードとMarkdownの両方に表示する。

- **直接証明**: 営業資料3カテゴリ該当＋ポートフォリオ活用度が高い（★4以上）
- **強い代替証明**: 営業資料3カテゴリ該当＋ポートフォリオ活用度中程度（★3）
- **弱い代替証明**: 営業資料3カテゴリだが活用度が低い、または非該当カテゴリで飲食・マネジメント経験が関連
- **証明不足**: 上記のいずれにも該当しない（Aランクには入れない）

### 不足資産（`buildMissingAssets`）

証拠が「直接証明」でない案件について、案件カテゴリとポートフォリオの対応関係のみから不足を抽出する
（存在しない実績の補完や複雑な推測はしない）。成長候補（Bランク）タブで案件ごと・全体集計の両方に表示する。

### 提案文の軸（`buildStrengthHint`）

固定の定型文をそのまま出すのではなく、「職能の組み合わせ → 今回できること → クライアントへの価値」を
案件のジャンル・マッチしたキーワード・飲食/AI適合の有無から毎回組み立てる。

高評価の理由は★の数（重要度）付きで表示される（例: `★★★★★ ライティングページを営業資料にできる` `★★★★☆ 継続案件の可能性`）。

## カスタマイズ

`config.js` を編集することで以下を変更できます：

- **検索キーワード追加** → `SEARCH_KEYWORDS` 配列に追加
- **除外条件追加** → `EXCLUDE_PATTERNS` に追加（文字列は部分一致、正規表現も混在可）
- **ジャンル優先度の調整** → `CATEGORY_TIERS`（ライティング/画像制作/AI活用・業務改善/通常/優先度低の各 `patterns` にキーワードを追加）
- **ポートフォリオ活用度の判定基準調整** → `PORTFOLIO_FIT_TIERS`（カテゴリごとの高/中/低一致キーワード）
- **未経験歓迎系キーワード追加** → `BEGINNER_PATTERNS`
- **受注しやすさの補助シグナル追加** → `SUPPORT_PATTERNS`（サポート体制・マニュアル完備等）
- **継続案件シグナル追加** → `CONTINUITY_PATTERNS` に追加
- **クライアント信頼性シグナル追加** → `CLIENT_TRUST_PATTERNS`（本人確認済み等）に追加
- **今の強みを活かせるAIキーワード追加** → `AI_FRIENDLY_KEYWORDS`（ChatGPT/Canva等。SNS運用系は含めない）に追加
- **優先しない技術系キーワード追加** → `AI_TECHNICAL_KEYWORDS`（Python開発/システム開発等、加点せず注意喚起のみ）に追加
- **リスクワード追加** → `RISK_PATTERNS` に追加（詐欺・トラブル警戒サイン）
- **SNS運用代行の除外条件追加** → `SNS_OPERATION_EXCLUDE_PATTERNS` に追加
- **SNS単発制作の判定キーワード追加** → `SNS_SINGLE_CREATION_PATTERNS` に追加
- **長期資産性の明言シグナル追加** → `ASSET_SIGNAL_PATTERNS`（「実績として掲載可」等）に追加
- **提案文の軸に使う職能フレーズ調整** → `SKILL_PHRASES` を変更
- **評価の重み調整** → `WEIGHTS`（②職能一致・①証拠の強さ・⑥単価・⑤継続性・⑧長期資産性・④受注可能性・③適性・⑦未経験歓迎）を変更
- **最低報酬ライン変更** → `PHASES.zero.minPriceYen` など、フェーズごとに変更
- **取得件数変更** → `MAX_JOBS`（応募候補の上限）・`MAX_GROWTH`（成長候補の上限）・`MAX_HOLDS`（保留の上限）を変更

## トラブルシューティング

| 症状 | 確認場所 |
|---|---|
| Gmail が届かない | `logs\run.log` を確認 |
| 案件が0件 | ネット接続・クラウドワークスのメンテ確認 |
| 今日の応募候補（S/A）が0〜数件しかない | 仕様どおり（無理な枠埋めをしないため）。良案件が少ない日。成長候補（Bランク）タブの不足資産を見て営業資産づくりを進める |
| SNS運用の案件なのに除外タブに出ない | 単発制作（バナー・投稿画像等）と判定された可能性あり。`SNS_OPERATION_EXCLUDE_PATTERNS`（`config.js`）にキーワードを追加すれば除外できる |
| 前に見た案件がまた出てくる | `data/seen_jobs.json` が削除・上書きされていないか確認 |
| 応募済みの案件が再表示される | 案件管理シートのC列にURLが記入されているか、`node mark-applied.js <ID>` で登録したか確認 |
| 見送った案件が再表示される | `node mark-skipped.js "<ID>|理由"` で `data/job_status.json` に登録したか確認 |
| 「案件管理シートの取得に失敗しました」と出る | シートの共有設定が「リンクを知っている全員が閲覧者」になっているか確認 |
| GitHub Pages が更新されない | `git push` のエラーを `logs\run.log` で確認 |
| スタートアップで起動しない | `shell:startup` でショートカットの存在を確認 |
